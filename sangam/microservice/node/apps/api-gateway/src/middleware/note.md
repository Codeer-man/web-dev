In this microservice architecture, the API Gateway is responsible for authenticating and authorizing requests before forwarding them to internal services. The client sends a JWT in the `Authorization: Bearer <token>` header, and the gateway verifies the token and checks whether the user's role is allowed to access the requested route using RBAC rules. Before doing this, the gateway removes internal headers such as `x-user-id`, `x-user-role`, and `x-gateway-secret` so that a client cannot fake them. After successfully verifying the JWT, the gateway adds the authenticated user's ID and role as internal headers (`x-user-id` and `x-user-role`) and adds a shared `x-gateway-secret`. The gateway secret is then checked by the internal microservice, such as the Auth Service, to make sure the request came through the trusted gateway rather than directly from an outside client. Therefore, the JWT proves the user's identity to the gateway, RBAC determines what the user is allowed to access, the user headers carry the verified identity to internal services, and the gateway secret protects the internal services from direct unauthorized requests.
